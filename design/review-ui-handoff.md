# 복습 화면 시안 — 인수인계

이 문서는 **화면 개선 기획**이다. 실제 게임 동작의 기준은 `index.html`과 `HANDOFF.md` 3.7·4절이다. 사용자는 소풍 가방 사건 기획을 잠시 뒤로 두고, 도서관 사건을 마친 뒤 나오는 복습 UI를 먼저 검토하고 있다. 현재 요청은 시안과 기획을 Claude Code가 이어받을 수 있게 정리하는 것이며, 이번 작업에서 앱 본편은 수정하지 않는다.

## 바로 열어 볼 것

- 별도 시안: [`design/review-preview.html`](review-preview.html). 저장소 루트에서 `node server.js` 실행 후 `http://localhost:5173/design/review-preview.html`. 파일을 직접 열어도 상대 경로의 `../assets/`를 읽는다.
- 실제 앱: `http://localhost:5173/`. 사용자가 보는 탭은 건드리지 말고 새 탭·격리된 저장소에서 확인한다.
- 화면 규칙·현재 구현: `HANDOFF.md` 3.7절(복습)과 4절. 코드에서는 `index.html`의 `.rv-*` 스타일, `openReview()`·`renderReview()`·`closeReview()`를 본다.
- 중학 영어 전체 커리큘럼은 `CURRICULUM.md`, 대표 사건 5개는 `CASE_THEMES.md`, 소풍 가방 상세안은 `design/case-01-picnic-bag.md`. 소풍 가방은 아직 기획만 있으며 앱에 적용하지 않았다. 범인 사건이 아니므로 해결은 ‘가방 주인 확인’이다.

## 사용자 결정과 현재 구현

| 항목 | 지금 상태 |
|---|---|
| 앱 디자인 | Paperlogy 글꼴, 크림 종이·세이지 바깥 배경, 손그림 버튼·카드·압정·별·도장 자산을 쓴다. 별도 시안도 저장소의 실제 `assets/`를 참조한다. |
| 복습 흐름 | 사건 해결 직후 결과 → 처음 틀린 문장 다시 듣기(없으면 생략) → 문법 → 새 단어. `학습 > 복습 보기`에서도 같은 화면을 다시 연다. |
| 새 단어 뜻 | **한국어 뜻을 처음부터 표시한다.** `해석` 버튼을 누르게 하지 않는다. `index.html`에 구현 완료(커밋 `20d89b4`). 문장·증거·대화의 한국어 해석은 기존처럼 버튼 뒤에 둔다. |
| 단어 담기 | 개별 `담기`·`담음`, `모두 담기`·`모두 빼기`, 종료 시 단어장 저장은 현재 동작을 유지한다. |
| 게임 정보 | 사건의 전말·정답·인물 역할을 결과 설명문에 쓰지 않는다. 복습은 듣기·문법·단어를 다룬다. |

## 별도 시안에서 비교할 화면

1. **사건 기록**: 압정으로 꽂은 사건 서류 안에 **사건 사진**을 크게 넣고 그 아래 사건 번호·제목(사용자 결정: 시안 B). COMPLETE 도장은 사진 오른쪽 위 모서리에 겹쳐 찍는다(사용자 결정). 사진은 범인을 잡은 사건이면 범인의 머그샷(키 눈금 벽 + 인물 그림 가운데 정렬 + 이름 번호판, 지금은 `fiona-sad.png`를 조합), 물건을 찾은 사건이면 그 물건 사진(증거 사진처럼 현장 그림에서 잘라 냄). 그 아래 별, 그리고 **같은 크기 타일 3개**(사용자 결정: 첫 페이지 시안 B, 설명 문장 없음): `26 / 30 받아 적기`(처음 확인에서 맞힌 칸) · `2 다시 들을 문장`(꿀색 강조, 없으면 `✓ 모두 맞힘`) · `4 새 단어`. 문법 수는 넣지 않는다.
2. **다시 듣기**(사용자 요청: 심플하게): 제목 `다시 들을 문장 n / 전체` 아래 질문 영어 한 줄(글만), 그 아래 흰 카드 안 맨 위에 대답의 ▶·`천천히`(사용자 요청: ▶가 질문 옆에 있으면 질문을 읽는 것처럼 보여서 아래로), 그 아래 빈칸 있는 노트 문장 한 줄(사용자 결정: `처음 쓴 답`은 보여 주지 않는다 — 단어 카드 4장 중 2장을 지우면 답이 드러남), 그 아래 단어 카드. 누가 말했는지·설명 문장·맞고 틀림 문장은 없다. 틀린 빈칸은 빨갛게, 다 맞으면 초록이 되고 단어 카드가 사라지며 아래 버튼이 `확인` → `다음`. 맞힌 뒤 학습자가 직접 넘긴다.
3. **표현 정리**(제목 `이번 사건의 문법`): 단어 담기와 같은 깔끔한 줄 카드(사용자 요청: 단어 페이지처럼)로 형태 셋을 한 페이지에(사용자 요청). 줄마다 ▶(예문), 형태와 짧은 이름, 그 아래 사건 예문, 오른쪽 `해석`(그 줄 아래에 한국어). 넘김 없이 아래 `다음`은 단어 담기로.
4. **단어 담기**(제목 `사건에 나온 단어 n / 전체`, 사용자 요청: 새 단어가 아니라; 설명 문장 "기억하고 싶은 단어를 수첩에 담아요."·"n개를 수첩에 담았어요." 없음): 영어 단어 아래에 한국어 뜻을 기본 표시하고, 재생과 담기만 남긴다. 이 기본 뜻 표시는 실제 앱에도 이미 적용됐다.

▶는 모든 줄에서 **오른쪽, 그 줄의 버튼(`해석`·`담기`·`천천히`) 바로 옆**에 둔다(사용자 요청, 이번 사건의 열쇠 쪽지와 같음). 복습 단계 표시는 위 진행 막대 대신 **아래 버튼 바로 위의 점**이다(사용자 결정: 이번 사건의 열쇠 쪽 표시와 같게, 지금 단계는 꿀색으로 조금 크게). 시안 위쪽의 ‘사건 기록·다시 듣기·표현 정리·단어 담기’ 버튼은 **시안 탐색용**이며 게임 화면 구성에 포함하지 않는다. 시안의 별 2개·30칸 중 26칸·오답 2개·단어 4개는 화면 확인용 예시 수치다. 레이의 문장은 현재 도서관 사건에서 가져왔지만, 시안의 문항·단어 목록은 전체 게임 상태를 재현하지 않는다. 시안의 ▶는 브라우저 음성 기능을 써서 조작만 보여 준다. 앱의 녹음 파일 연결·저장 로직은 바꾸지 않는다.

## 앱 적용을 논의할 때 구분할 점

- 실제 결과 화면은 서류·별·정답률·타일 3개가 가운데 있는 구조다. 시안의 ‘다시 들을 문장’ 강조와 버튼 문구는 **제안**이지 승인된 구현이 아니다.
- 실제 다시 듣기는 처음 틀린 질문마다 카드를 만들고, 맞히면 짧은 효과 뒤 자동으로 다음 카드로 넘어간다. 시안은 레이 질문 한 장만 보여 주며 직접 넘기는 흐름을 제안한다. 여러 오답·오답 없음·저장된 복습을 모두 고려해야 한다.
- 실제 문법 단계는 사건에서 많이 나온 문법 **세 항목**을 한 화면에 보여 준다. 시안은 시간 전치사 한 항목의 **세 형태**를 한 페이지에 쪽지로 보여 준다. 두 방식은 내용 선정도 다르므로 적용 여부를 사용자와 검토해야 한다.
- 실제 복습 단계 수는 오답 문장이 없을 때 3, 있을 때 4다. 시안의 진행 막대는 항상 4칸이다. 적용한다면 조건부 단계 수를 유지한다.
- 시안의 단어 ▶는 단어를 읽어 주지만 실제 복습의 ▶는 해당 **문장**을 재생한다. 단어장 ▶는 단어만 재생한다. UI 개선을 적용할 때 오디오 의미를 임의로 바꾸지 않는다.
- 화면 안의 조작법 문구는 튜토리얼이 담당한다. 시안의 설명 문구를 앱에 옮길 때 이 규칙에 맞는지 확인한다.

복습 화면 전체 개편은 아직 사용자 선택을 받지 않았다. Claude Code가 이어받을 때는 이 시안과 실제 앱 화면을 함께 보며 사용자의 다음 피드백을 반영한다. 구체적 구현 요청이 오면 위 차이를 먼저 해결하고, 기존 진행·기록과 사건 완료 흐름을 유지한 채 검증한다.
