# 작업 마무리 (Pioo)

Codex와 Claude Code가 번갈아 작업하는 프로젝트다. 이 마무리가 다음 작업자에게 넘겨주는 신호이므로 단계를 건너뛰지 않는다. 기준 규칙은 `AGENTS.md`의 "마무리 절차"이고, 이 문서는 그 체크리스트다.

## 1. 바뀐 것 파악

```bash
git status --short
git diff --stat
```

- 이번 작업에서 바뀐 파일만 다룬다. 다른 에이전트가 고친 것으로 보이는 미커밋 파일이 있으면 사용자에게 알리고, 그 파일은 커밋에 넣지 않는다.

## 2. 확인

- `index.html`을 고쳤으면 인라인 스크립트 구문을 검사한다.

  ```bash
  node -e "const h=require('fs').readFileSync('index.html','utf8');[...h.matchAll(/<script>([\s\S]*?)<\/script>/g)].forEach(x=>new Function(x[1]));console.log('syntax ok')"
  ```

- 화면에 영향이 있으면 브라우저 **새 탭**에서 확인한다(`tabs_create` → `navigate http://localhost:5173/`). 사용자가 보고 있는 미리보기 탭은 건드리지 않는다.
  - 테스트 버튼(폰 프레임 밖)을 쓰면 빠르다: 노트 자동 채우기, 전체 대화 완료, 증거 모두 수집, 튜토리얼 초기화.
  - 콘솔 오류를 본다(`read_console_messages`, onlyErrors).
  - **localStorage는 탭끼리 공유된다.** 시험 중 생긴 `pioo.solvedCases`(해결 기록) 같은 값은 지우고, 지웠다고 보고한다.
  - 확인이 끝나면 그 탭을 닫는다.
- 확인하지 못한 것은 숨기지 않고 적어 둔다(CHANGELOG와 보고에 쓴다).

## 3. HANDOFF.md를 지금 상태로 고쳐 쓰기

- **이력·날짜 메모를 넣지 않는다.** "예전에는 ~였다"는 지운다. 지금 동작만 남긴다.
- 바뀐 종류에 따라 볼 절:

  | 바뀐 것 | 볼 절 |
  |---|---|
  | 기능·흐름 | 0절 요약(구현 완료 / 아직 없는 것), 3절 해당 흐름 |
  | 사용자가 정한 규칙 | 4절 설계 규칙(그리고 `AGENTS.md`의 "지켜야 할 규칙") |
  | 데이터·함수·상태 | 5절 표(데이터, 상태, 주요 함수) |
  | 음성 | 6절 표와 파일·job 목록 |
  | 그림 | 7절 표 |
  | 테스트 버튼 | 8절 테스트 도구 표 |
  | 다음 할 일 후보 | 10절(끝난 항목은 지우거나 고친다), 10.1절 미확정 논의 |

- 새 그림·음성이 있으면 `assets/characters/README.md`, `assets/places/README.md`, `assets/ui/README.md`에 출처를 적는다(사용자 제작인지 Claude 제작인지, Higgsfield job id, 프롬프트 요지, 크기, 잘라 낸 좌표나 입 좌표).

## 4. CHANGELOG.md 항목 추가

1. 맨 위 항목 제목의 `(이 커밋)`을 그 커밋의 해시로 바꾼다(`git log --oneline -3`으로 확인).
2. `---` 바로 아래, 맨 위에 새 항목을 넣는다.

```
## YYYY-MM-DD HH:MM · Claude · (이 커밋)

- 사용자 요청: 무엇을 바꿨는지(사용자가 정한 것은 "사용자 결정"이라고 적는다)
- 쓴 크레딧이 있으면 대략의 양
- 확인(새 탭): 무엇을 확인했는지 / 못 한 것
- **다음**: 이어받는 쪽이 바로 할 일. 없으면 "사용자 지시 대기"(사용자 확인이 필요한 질문이 남았으면 그것을 적는다)
```

- 시각은 한국 시간이다.
- "다음"은 다음 작업자가 "이어서 해줘"만 듣고 움직일 수 있게 구체적으로 쓴다.

## 5. main에 커밋

```bash
git add -A
git commit -q -m "<무엇을 바꿨는지 한 줄 (영어)>

Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>"
git log --oneline -1
```

- 브랜치를 만들지 않는다. 마무리에서는 push하지 않는다. GitHub 푸시는 사용자가 요청할 때만 `/push-github`로 한다.
- 다른 에이전트의 미커밋 파일이 있었다면 `git add -A` 대신 이번 작업 파일만 지정해 넣는다.
- 훅이 실패하면 우회하지 말고 원인을 고친다.

## 6. 기억할 것이 생겼으면 메모리

- 사용자가 새로 정한 작업 방식이나 선호(예: "앞으로 ~해줘")가 있으면 Claude 메모리에 남긴다. 코드·문서에 이미 적힌 것은 메모리에 중복하지 않는다.

## 7. 사용자에게 한국어로 보고

- 맨 앞에 결과와 커밋 해시를 쓴다.
- 바뀐 것을 사용자 관점(화면에서 무엇이 달라졌는지)으로 짧게 쓴다.
- 확인한 것과 못 한 것, 사용자가 정해야 할 것을 따로 적는다.
- 아티팩트 업로드는 사용자가 요청할 때만 한다(마무리에 포함하지 않는다).
