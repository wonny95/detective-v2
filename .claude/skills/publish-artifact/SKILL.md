# 아티팩트 새로 배포 (Pioo)

사용자가 요청할 때만 실행한다. 작업 마무리(`/wrap-up`)에 포함하지 않는다.

## 0. 먼저 작업 마무리

- `git status --short`가 비어 있지 않으면 **`/wrap-up`을 먼저 끝낸다.** 배포본은 커밋된 상태를 기준으로 만들고, 그 커밋을 배포 기록에 남긴다.
- 순서: 작업 마무리(커밋) → 배포 → 배포 기록 커밋.

## 1. 제목 정하기

- 형식: `영어듣기 추리 게임 앱_YYMMDD`. 날짜는 **한국 시간 오늘**이다.

  ```bash
  echo "영어듣기 추리 게임 앱_$(TZ=Asia/Seoul date +%y%m%d)"
  ```

- **같은 날짜는 덮어쓴다**(사용자 결정, 묻지 않는다). `HANDOFF.md` 9절 배포 기록이나 `Artifact` `action:"list"`에서 오늘 제목의 아티팩트를 찾는다.
  - 있으면: 그 URL을 `action:"read"`로 먼저 읽고(도구 요구 사항), 3단계에서 그 `url`로 배포한다. 링크와 공유 설정이 그대로 유지된다.
  - 없으면: 새로 만든다.
- 사용자가 다른 제목을 말하면 그 제목이 우선이다.

## 2. 배포본 만들기

먼저 `artifact-design` 스킬을 불러온다(Artifact 도구의 요구 사항). 게임은 자체 디자인이 있으므로 페이지 구성·색은 바꾸지 않는다.

```bash
OUT="<스크래치패드>/artifact-$(TZ=Asia/Seoul date +%y%m%d)"
python -I .claude/skills/publish-artifact/build.py . "$OUT" "영어듣기 추리 게임 앱_$(TZ=Asia/Seoul date +%y%m%d)"
```

- `build.py`가 하는 일:
  - `index.html`을 복사해 `<title>`을 바꾼다.
  - `<!doctype>`·`<html>`·`<head>`·`<body>` 감싸는 태그를 뺀다. 아티팩트가 자체 문서 틀을 씌우기 때문이다.
  - 폰 프레임 밖 테스트 버튼은 **기본으로 보인다**(사용자 결정). 사용자가 빼 달라고 할 때만 `--hide-dev`를 붙인다.
  - 페이지가 쓰는 `assets/…`·`audio/…` 파일을 모두 찾아 `files.json`에 `{게시 경로: 원본 경로}`로 적는다.
  - 빠진 파일이나 용량 한도(파일당 15MB, 한 번에 255개·64MB)를 넘으면 멈춘다.
  - 지금 기준으로 약 58개 파일, 20MB다.
- 출력에 나온 `page`(배포할 페이지)와 `files.json`을 쓴다.

## 3. 배포

- `Artifact`를 호출한다.
  - `action`은 생략한다(publish).
  - `file_path`: `$OUT/index.html`(날짜별 폴더).
  - `url`: 오늘 아티팩트가 이미 있으면 그 URL(덮어쓰기). 없으면 넣지 않는다(새로 만들기).
  - `title`: 1단계의 제목.
  - `icon`: `game`.
  - `description`: 예) "영어로 듣고 받아 적은 노트로 범인을 찾는 숲속 추리 게임 프로토타입."
  - `files`: `files.json`의 내용 그대로.
  - 한 번에 너무 많으면 같은 `url`로 나눠 올린다.
- 결과로 받은 URL을 기록해 둔다.

## 4. 공개 범위: 링크가 있는 사람만

- 아티팩트는 처음에 **비공개(본인만)**로 만들어진다.
- Claude의 Artifact 도구에는 공유 범위를 바꾸는 기능이 없다. 그래서 **"링크가 있는 사람" 설정은 자동으로 할 수 없다.**
- 사용자에게 이렇게 안내한다: 아티팩트 페이지 오른쪽 위 **공유(Share)** → 접근 권한을 **"링크가 있는 사람"**으로 바꾼다.
- 나중에 도구가 공유 설정을 지원하면 이 절을 고친다.

## 5. 확인

- 배포 결과의 링크를 `Artifact` `action:"read"`로 읽어 제목과 페이지가 맞는지 본다.
- 가능하면 브라우저 **새 탭**에서 아티팩트 링크를 열어 사건 목록 → 브리핑 → 음성 하나와 그림이 나오는지 확인한다. 사용자의 미리보기 탭은 건드리지 않는다.

## 6. 기록과 보고

- `HANDOFF.md` 9절 배포 기록에 적는다: 제목, URL, 기준 커밋(`git log --oneline -1`), 테스트 버튼 포함 여부. 새 날짜면 맨 위에 추가하고, 같은 날짜를 덮어썼으면 그 줄의 기준 커밋만 바꾼다.
- `CHANGELOG.md`에 항목을 추가하고 `main`에 커밋한다(`/wrap-up`의 4·5단계).
- 사용자에게 한국어로 보고한다: 링크, 제목, 포함한 파일 수와 용량, 테스트 버튼 포함 여부, **공유 설정은 직접 바꿔야 한다는 안내**.
